# あなたのtwinをRenderにデプロイする

_Cursorでこれを見ている場合は、File Explorerでファイルを右クリックし「Open Preview」を選択すると、整形されたバージョンを表示できます_

HuggingFace SpacesはGradioアプリをホストするために現在有料のPROサブスクリプションを要求するようになったため、代替として[Render](https://render.com)を紹介します。Renderには無料プランがあり、クレジットカードの登録も不要で、twinをコードの変更なしにそのまま実行できます。

一つ事前に知っておいてほしいこと: 無料プランでは、15分間訪問者がいないとアプリがスリープします。次の訪問者がアクセスするとアプリが再起動し、30〜60秒かかります。その後は通常どおり応答します。

## 必要なもの

- GitHubアカウント(このコースをクローンした際にすでに持っているはずです)
- `.env`ファイルにあるOpenAI APIキー、PushoverのユーザーIDとトークン
- 自分自身の`linkedin.pdf`と`summary.txt`で更新済みの`twin`ディレクトリ

## ステップ1: twinを専用のGitHubリポジトリに入れる

Renderは GitHubリポジトリからデプロイします。このコースのリポジトリはそのままでは使えません。他のすべてが含まれており、コース全体のものだからです。`twin`ディレクトリの内容だけを含む、小さな別リポジトリが必要です。

gitコマンドを一切使わない、最も簡単な方法:

1. [github.com/new](https://github.com/new)にアクセスし、リポジトリを作成してください。名前は`twin`にしてください。あなたのLinkedIn PDFは個人情報なので、**Private**を選んでください。リポジトリを空にしないよう、READMEを追加するチェックボックスをオンにしてください。
2. 新しいリポジトリのページで、**Add file**、次に**Upload files**をクリックしてください。
3. コンピューター上の`1_foundations/twin`から次の7つのファイルをドラッグしてください: `app.py`、`context.py`、`tools.py`、`styles.py`、`requirements.txt`、`summary.txt`、`linkedin.pdf`。`__pycache__`フォルダが見えても含めないでください。
4. **Commit changes**をクリックしてください。

コマンドラインを使いたい場合は、まず`twin`フォルダをこのコースのリポジトリの外側にコピーしてください(例: `cp -r twin ~/twin`)。その後`git init`を実行し、ファイルをコミットして、通常の方法で新しいプライベートGitHubリポジトリにpushしてください。コースのリポジトリの中にgitリポジトリを作ると混乱を招くため、コピーする手順が重要です。

`.env`ファイルやAPIキーを決してリポジトリに入れないでください。キーはステップ4でRenderのダッシュボードに入力します。

## ステップ2: Renderアカウントを作成する

1. [render.com](https://render.com)にアクセスして**Sign In**をクリックし、GitHubアカウントでサインアップしてください。これにより次のステップが簡単になります。
2. 求められたらメールアドレスを確認してください。クレジットカードの入力は不要です。

## ステップ3: Webサービスを作成する

1. Renderのダッシュボードから**New +**をクリックし、**Web Service**を選択してください。
2. プロンプトが出たらGitHubアカウントを接続し、Renderに`twin`リポジトリへのアクセスを許可してください。
3. `twin`リポジトリを選択してください。
4. 設定を入力してください:
   - **Language**: Python 3
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `python app.py`
   - **Instance Type**: Free
5. まだDeployはクリックしないでください。先に以下の環境変数を追加します。

## ステップ4: 環境変数

同じページの**Environment Variables**セクション(または後で該当サービスの**Environment**タブから)で、以下の5つを追加してください:

| キー | 値 |
|---|---|
| `OPENAI_API_KEY` | `.env`にあるあなたのOpenAIキー |
| `PUSHOVER_USER` | `.env`にあるあなたのPushoverユーザーID |
| `PUSHOVER_TOKEN` | `.env`にあるあなたのPushoverトークン |
| `GRADIO_SERVER_NAME` | `0.0.0.0` |
| `GRADIO_SERVER_PORT` | `10000` |

最後の2つについては説明が必要です。Renderはアプリがポート10000でWebトラフィックをリッスンすることを期待しており、Gradioは起動時にこの2つの変数を読み込むので、これによってGradioがどこでリッスンするかを伝えます。コードの変更は不要です。

## ステップ5: デプロイ

1. **Deploy Web Service**をクリックしてください。
2. ログを見てください。最初のビルドでは依存関係のインストールに数分かかります。
3. ログにGradioの起動メッセージが表示されたら、アプリは稼働中です。URLはページ上部にあり、`https://twin-xxxx.onrender.com`のような形式です。
4. 開いてtwinに挨拶してみてください。メールアドレスを伝えたときにPushover通知が届くか確認してください。

## twinを更新する

ファイルを変更した場合(例えば`summary.txt`を改善した場合)、新しいバージョンをGitHubリポジトリにアップロードするか、コマンドラインを使っている場合はpushしてください。Renderが変更を検知し、自動で再デプロイします。

## トラブルシューティング

- **ページの読み込みがとても遅い。** 15分間誰も訪問していない場合、アプリはスリープしており、起動に最大1分かかります。無料プランでは正常な動作です。
- **ビルドが失敗する。** サービスページのログを確認してください。最も多い原因はファイルの欠落なので、7つのファイルすべてがGitHubリポジトリに入っているか確認してください。
- **ビルドは通るがページにエラーが表示される。** 通常は環境変数の欠落やタイプミスが原因です。**Environment**タブで5つすべてを確認し、**Manual Deploy**で再起動してください。
- **Pushover通知が来ない。** **Environment**タブで`PUSHOVER_USER`と`PUSHOVER_TOKEN`を確認してください。ユーザーキーは`u`で始まり、トークンは`a`で始まることを覚えておいてください。
