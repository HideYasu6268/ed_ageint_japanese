# Week 5 - Agent Frameworksへようこそ

## Day 4: Mastra (TypeScript)

同じ週、同じ5つのステップ、新しいフレームワーク、そして今日は新しい言語です。今週全体のアイデアは、一つのエージェントフレームワークを知れば、基本的にすべてを知っていることになるというものです。そのため、毎日同じエージェントを同じ5つのステップで作り、その作法が響き合う様子を観察します:

1. **エージェントを作る** - モデルとシステムプロンプトを与える。
2. **実行する** - メッセージを送り、返信を受け取る。
3. **ツールを追加する** - エージェントが呼び出せる、型付けされた普通の関数。
4. **MCPを追加する** - 他の誰かが書いたツールサーバーに接続する。毎回同じ方法で。
5. **ゴールを持たせてループの中に置く** - 目標を与え、仕事が終わるまで一歩ずつ動かせる。

今日は、この5つのステップを、Gatsbyの開発チームによって作られたTypeScriptネイティブの代表的なエージェントフレームワークである**Mastra**を使い、**TypeScript**で書きます。これは、今週のテーゼを言語の壁を越えて試す日です。同じエージェント、同じSQLiteボード、同じワーカーを、今度はWebの言語であるTypeScriptで実装します。

### この日の進め方

この日はTypeScriptのみの1日で、Pythonのノートブックとは違う形で進みます。ノートブックの代わりに、このラボはこのファイルと、その隣に置かれた5つの小さなTypeScriptプログラム、`step1.ts`から`step5.ts`で構成されています。各ステップについて、ここで説明を読み、対応するファイルを開いて全体のコードを確認し、ターミナルから実行してください。ボードとツールはそれぞれ`board.ts`と`tools.ts`という独自のファイルにあり、各ステップはそれらをインポートします。それらも開いてみてください。今日一日全体の土台になっているものです。

## セットアップ

ちょっとした一度限りのセットアップです。関係するディレクトリは2つあるので、以下のコマンドはそれぞれどちらで実行すべきかを示しています: クローンした`agents`という**プロジェクトのルート**と、このファイルが置かれているフォルダである**このMastraディレクトリ**、`agents/5_agent_frameworks/4_mastra`です。

- **Node 24 LTS。** コードはNode経由で実行されるTypeScriptで、ボードはNode組み込みのSQLiteを使用しており、Node 23.4以降はフラグなしで使えます。`node --version`でバージョンを確認してください。
- **この日のためのNodeパッケージ。** **このMastraディレクトリ、`agents/5_agent_frameworks/4_mastra`**で以下を実行し、依存関係を一度だけインストールしてください:

  ```bash
  npm install
  ```

- **`OPENAI_API_KEY`** をリポジトリルートの`.env`に設定してください。第1週から使っているのと同じキーです。プログラムは`dotenv`でこれを読み込み、フォルダから上に向かって最も近い`.env`を探します。

以下のすべてのステップは、**このMastraディレクトリ**内のターミナルから実行してください。各ステップは`npm run stepN`で、内部的には単に`tsx stepN.ts`です。

## 今週のプロジェクト: SQLite todoボード

`board.ts`を開いてください。これは1日目から3日目までの`board.py`のTypeScript版であり、Node組み込みの`node:sqlite`を使った、1ファイル・1テーブル・サーバー不要の実装です。ワーカーには1つの**ゴール**が与えられます。そこに到達するために、そのゴールの下に自分自身の**ステップ**todoを書き込み、進めるたびにそれぞれチェックを入れ、最後にゴールを閉じます。`showBoard()`は、第1週のリッチなスタイルで表示します。各ゴールの下にステップがインデントされ、完了したtodoは緑色の取り消し線付きで表示されます。

次に`tools.ts`を開いてください。ここには、Mastraのやり方(`createTool`とzodの入力スキーマ)で書かれた3つのボードツールが入っています: ボードを読む`show_todos`、ゴールをステップに分解する`plan_steps`、todoを完了にする`complete_task`です。また、ステップ4で追加するファイルシステムMCPサーバーである`makeFilesystem`もここにあります。

## ステップ1: エージェントを作る

`step1.ts`を開いてください。Mastraでは、エージェントは`Agent`です: 名前、`instructions`(システムプロンプト)、そしてモデルです。モデルはルーティング文字列`openai/gpt-5.4-mini`で、Vercel AI SDKを通じて解決され、OpenAIが選ばれ、環境変数から`OPENAI_API_KEY`が読み込まれます。まだ何も実行されません。ただ構築するだけです。

```bash
npm run step1
```

`Created agent: Assistant`と表示されるはずです。

## ステップ2: 実行する

`step2.ts`を開いてください。メッセージを送り、返信を待ち、結果の`.text`を表示します。まだツールがないため、ループする対象がなく、エージェントはただ答えるだけです。これはまだ単なるLLM呼び出しです。

```bash
npm run step2
```

短いスペイン語の挨拶、`Hola.`のようなものが表示されるはずです。

## ステップ3: ツールを追加する

`step3.ts`を開いてください。`tools.ts`のボードツールをエージェントに与え、ゴールを1つ登録し、ボードに何があるか尋ねます。答える前に、エージェントが自分の判断で`show_todos`を呼び出すのを観察してください。この「判断する、呼び出す、読む、答える」という流れが、エージェントループが回り始めるところです。3つのツールすべてはステップ5で一つにまとまります。

```bash
npm run step3
```

エージェントは保留中のゴールを1つ報告し、その下に`showBoard()`が表示します。

## ステップ4: MCPを追加する

`step4.ts`を開いてください。MCPは単に増えたツールにすぎません。あなたが書いたのではなく、小さなプロトコルで接続されたツールです。今週すべてのフレームワークが使う同じNodeサーバーであるファイルシステムのリファレンスサーバーをエージェントに与え、単一の`workspace`フォルダに限定します。Mastraでは、MCPサーバーは`MCPClient`です。`await mcp.listTools()`でそのツールを取得し、エージェントに渡します。

Mastraは今週で最もシンプルなMCPの接続方法を持っています。この日に必要な2つの修正は、stdioサーバーへの単純なオプション(`tools.ts`の`makeFilesystem`を参照)です: `stderr: "ignore"`はサーバーの起動バナーを無視し、`cwd`はワークスペース内でサーバーを起動するので、エージェントの相対的なファイル名がそこで解決されます。サブクラス化もモンキーパッチも不要です。

```bash
npm run step4
```

エージェントはファイルシステムサーバーを通じて`notes.txt`を読み、1文で要約します。

## ステップ5: ゴールを持たせてループの中に置く

`step5.ts`を開いてください。ここでいよいよ成果が出ます。1つのエージェントに3つのボードツールとファイルシステムサーバーすべてを与え、ゴールを渡して実行させます。ボード上で自分自身のステップを計画し、ファイルツールでそれらに取り組み、それぞれチェックを入れ、作業が終わったらゴールを閉じます。それが自律的に動くエージェントループです: 読む、計画する、行動する、チェックを入れる、繰り返す。

```bash
npm run step5
```

ボードにステップが埋まっていき、緑の取り消し線が付いていく様子と、スペイン語が`workspace/spanish.txt`に書き込まれる様子を見てください。

## 一つのクールなもの: Studio

Mastraの開発者体験はその看板であり、Studioはその中心です。あなたのエージェント用のローカルWeb UIで、今週紹介したものの中で最も洗練されています。このフォルダのターミナルから起動してください:

```bash
npm run dev
```

そして`http://localhost:4111`を開いてください。Workerエージェントを選び、ボード上のゴールに取り組むよう頼んでください。そこに待っている英語のメモを読み、スペイン語に翻訳し、その翻訳付きでゴールを完了にし、返信します。その間、各モデルのステップ、各ツール呼び出し、各結果がリアルタイムで表示され、後から再生できる完全なトレースが残ります。同じパネルでモデルを切り替えたり、設定を調整したりすることもできます。

今週全体と同じ精神での余談を2つ。モデルはルーティング文字列なので、ワーカーを任意のOpenAI互換エンドポイントに向けるのは1行の変更で済みます。このフォルダの`SWAP_AI.md`にその方法が示されています。そして、Mastraはネイティブなファーストクラスのa2Aを持っています: 登録したどのエージェントも、エージェントカードとJSON-RPCエンドポイントとともに自動的に公開され、追加の作業は不要です。今週はA2Aを使って構築しませんが、無料で手に入るのはうれしいことです。
